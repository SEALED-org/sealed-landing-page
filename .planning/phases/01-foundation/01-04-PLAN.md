<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser ↔ Supabase REST (PostgREST) | Anon client fetches `public.signup_counter` — single integer, no PII. |
| User input ↔ Local state | Email submit triggers an in-memory `setWaitlistCount(c => (c ?? 115) + 1)` only — no network call in Phase 1, no DB insert. |
| Network failure ↔ UI | A failed fetch falls back to 115 and logs to console — no error UI exposed to users (D-12). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-12 | Tampering | Local +1 increment after email submit | accept | The local +1 in `handleSubscribe` and the `FirstLetter` callback is intentional, purely cosmetic, and resets on page reload. A user inflating their own visible counter has no security impact (no DB write, no broadcast). Phase 2's Edge Function performs the real insert behind Turnstile + IP rate limit — server is the source of truth from page-reload onward. |
| T-01-13 | Information disclosure | DevTools Network tab exposing Supabase REST URL | accept | The anon REST endpoint and the anon key are already in the bundle by design (T-01-01 in plan 01). Showing the request in Network is no incremental disclosure. |
| T-01-14 | Denial of service | Slow Supabase response blocking page render | mitigate | The fetch runs inside `useEffect` (post-render), not inside render. The Counter component renders immediately with `target=115` (because `waitlistCount ?? 115`) so the hero is never blank. The 3s AbortSignal timeout in `getSignupCount` (plan 01) ensures even pathological network conditions fall back to 115 within 3 seconds. |
| T-01-15 | Repudiation | No audit trail of counter reads | accept | Counter reads are unauthenticated and PII-free. PostgREST logs the request server-side; no client-side audit is required. |
| T-01-16 | Information disclosure | console.error revealing internal error details to a casual user opening DevTools | accept | The console.error wording `Counter fetch failed:` plus the error object exposes Supabase error codes and URLs — but anyone opening DevTools can already see the underlying Network tab response. The console.error is intended for Nour's debugging (D-12 is explicit). No PII passes through this code path. |
</threat_model>
