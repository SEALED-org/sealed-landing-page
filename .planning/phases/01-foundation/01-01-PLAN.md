<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser bundle ↔ Build-time env substitution | Vite replaces `import.meta.env.VITE_*` with string literals at build time. Anything prefixed `VITE_` IS shipped to the browser by design. |
| Browser ↔ Supabase REST (PostgREST) | The anon client makes unauthenticated requests gated by Postgres role grants, not by secrecy. |
| Source code ↔ Missing env var (dev-time) | If `.env.local` is missing or incomplete, `import.meta.env.VITE_SUPABASE_URL` becomes the literal string `"undefined"`. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Information disclosure | `VITE_SUPABASE_ANON_KEY` bundled into browser JS | accept | This is the documented Supabase pattern — the anon key is meant to be public. Real access control happens through Postgres role grants and (in plan 03) `revoke all on app_private.waitlist_signups from anon` plus `security_invoker=false` on the view. The anon key by itself can only read what's been granted to the `anon` role. Document the design rationale in this PLAN; do not attempt to hide the key. |
| T-01-02 | Tampering (silent broken client) | `createClient("undefined", "undefined")` if env vars missing | mitigate | `src/lib/supabase.ts` throws at module load if either VITE_SUPABASE_URL or VITE_SUPABASE_ANON_KEY is missing or falsy (Task 2 action). This converts a silent failure ("client appears to work but every request fails with CORS") into a loud, named, actionable error at `npm run dev` startup. Verified by the grep gate in Task 2's `<verify>`. |
| T-01-03 | Denial of service (hung fetch) | `getSignupCount()` HTTPS to Supabase REST | mitigate | `.abortSignal(AbortSignal.timeout(3000))` cancels the underlying request after 3s, releasing the connection. The caller (plan 04's App.tsx useEffect) falls back to 115 (per D-11) and logs to console (per D-12). No retries — single attempt, fast fallback, never blocks render. |
| T-01-04 | Repudiation / audit | Counter read | accept | Counter reads are unauthenticated and idempotent. No state change, no PII. PostgREST logs the request server-side; no client-side audit trail needed in Phase 1. |
| T-01-17 | Tampering (silent contract drift) | `joinWaitlistLocal` stub signature drifting from Phase 2's real implementation | mitigate | The stub accepts `email: string` and returns `Promise<void>` — locked here in Phase 1. When Phase 2 replaces the body with the real fetch, it MUST keep this signature so the `await joinWaitlistLocal(email)` call sites in App.tsx don't need restructuring. The comment block above the stub explicitly documents this contract. Any future change to the signature is a breaking change visible at the call sites. |
</threat_model>
