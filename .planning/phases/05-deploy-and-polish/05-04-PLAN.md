<objective>
Add the service-role-key bundle-leak gate flagged as a standing blocker in STATE.md: an npm script that scans the built `dist/` for service-role-specific secret patterns and fails (non-zero exit) on any hit, so a leaked secret can never ship to Vercel. Chained into the build/deploy command in Plan 05.

Purpose: `VITE_*` vars are inlined into the public bundle at build time. The legitimate anon key is a JWT starting `eyJ` and is *supposed* to be in the bundle, so a naive `grep eyJ` false-positives every build (D-18). The gate must target patterns that should NEVER appear client-side: `sb_secret_`, `"role":"service_role"`, `service_role`, `SERVICE_ROLE_KEY`. Current `dist/` is clean (0 hits, verified in research).
Output: `scripts/check-bundle.mjs` (new), `package.json` `verify:no-secrets` script (and a convenience `build:check` chaining build + gate).
</objective>
