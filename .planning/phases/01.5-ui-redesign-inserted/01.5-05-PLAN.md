  <action>
    Replace the entire contents of `src/components/Counter.tsx` with a new implementation following the structure below. Do NOT import anything from `motion/react`. Import only from `react`: `useEffect`, `useRef`, `useState`.

    Declare the preserved interface: `interface CounterProps { target: number }`.

    Default-export a function `Counter({ target }: CounterProps)`. Inside the function body:

    (1) **State and refs:** `const [displayed, setDisplayed] = useState(0);` — initial value 0 so first paint shows `00000`. Hold the previously rendered character array in a ref: `const prevCharsRef = useRef<string[]>(['0','0','0','0','0']);`. Hold pending setTimeout ids in a ref: `const timersRef = useRef<number[]>([]);`. Hold per-cell DOM refs in an array of refs: declare `const cellRefs = useRef<Array<HTMLDivElement | null>>([null, null, null, null, null]);` — these are used to access each `.digit` element to toggle the `.flip` class and to read its child `.d-cur` / `.d-next` spans.

    (2) **Update effect:** Use `useEffect(() => { ... }, [target])` to react to target changes. Inside: compute `const nextChars = String(target).padStart(5, '0').split('');` and `const prevChars = prevCharsRef.current;`. Schedule a setTimeout per digit `i` (0..4): the timeout fires at `40 * i` ms (so digit 0 starts immediately, digit 1 starts at 40ms, etc. — UI-SPEC line 463 / CONTEXT.md `<specifics>` 4th bullet). Inside each per-digit timeout: if `nextChars[i] === prevChars[i]`, return early (no flip needed — matches the prototype's `if (cur.textContent === ch) return;` on Landing.html line 1784). Else: read the element via `cellRefs.current[i]`; set its child `.d-next` span's `textContent` to `nextChars[i]`; force a reflow with `void el.offsetWidth`; add the class `flip` via `el.classList.add('flip')`. Schedule a follow-up `setTimeout(() => { ... }, 500)` that runs after the keyframe completes: set the `.d-cur` span's `textContent` to `nextChars[i]`, remove the `flip` class, and update `prevCharsRef.current[i] = nextChars[i]`. Push every setTimeout id onto `timersRef.current`. Also call `setDisplayed(target)` (once, outside the per-digit loop) so React re-renders for accessibility (the `aria-label` value).

    (3) **Cleanup:** Return a cleanup function from the useEffect that runs `timersRef.current.forEach(window.clearTimeout)` then resets `timersRef.current = []`. This is critical for StrictMode safety (RESEARCH.md Risk #6) — React 19 double-invokes effects in dev; without cleanup the timers stack up and produce double flips.

    (4) **Render:** `padStart` the displayed value to 5 characters. Render a single `<div className=\"counter\">` containing two children:

       (a) `<div className=\"digit-row\" aria-label=\"Sign ups so far\">` containing 5 `<div ref={(el) => { cellRefs.current[i] = el; }} className=\"digit\" key={i}>` cells, each with two spans inside: `<span className=\"d-cur\">{chars[i]}</span>` and `<span className=\"d-next\">{chars[i]}</span>`. On the initial mount, both spans show the initial-state character so there is no visible flicker before the first flip schedule fires. The aria-label `Sign ups so far` is on the `.digit-row`, not on `.counter`, per UI-SPEC line 198.

       (b) `<div className=\"counter-label\">` containing `<span className=\"dot\" aria-hidden=\"true\" />` (the rotated 5×5 ink-35 square, styled in CSS) and `<span>Sign ups so far</span>`.

    (5) **Width logic:** Always render 5 cells. Drop the existing `width = target >= 10000 ? 5 : ...` logic — the prototype's design is fixed-width 5-digit (per UI-SPEC line 464). If a target value somehow exceeds 5 digits (target ≥ 100000), `String(target).padStart(5, '0')` will still produce ≥5 characters — taking the last 5 with `.slice(-5)` is acceptable defensive behavior, but per UI-SPEC the count is not expected to exceed 99999 in v1. Implementation: `const chars = String(target).padStart(5, '0').slice(-5).split('');`.

    (6) **No Motion:** The component must NOT import from `motion/react`. The CSS keyframes `digitOut` and `digitIn` (already declared in `src/index.css` per Plan 01.5-02) fire automatically when the `.flip` class is added to a `.digit` element — React's only role is to toggle the class and copy text to the spans at the right moment.

    (7) **No internal label prop:** The current Counter takes only `target`. Do NOT add `label` or `aria-label` props — the label text is hardcoded `Sign ups so far` per UI-SPEC and is not configurable in v1. If a future plan wants to make it configurable, it can add a prop with a default value at that time.

    Inline comments in the file are OPTIONAL but if added should be minimal (1–2 lines) and cite the prototype source: e.g., `// Per Landing.html setCount (lines 1774–1801): force reflow before adding .flip so the keyframe re-fires.`
