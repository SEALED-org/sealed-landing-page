**Analog (React conventions / prop signature to preserve):** `src/components/Counter.tsx:1-29`

**Imports pattern** (from RESEARCH.md Pattern 2 — explicitly NOT `useMotionValue`/`useTransform`/`animate`):


**Why NOT `motion/react`:** the current Counter uses `useMotionValue` + `useTransform` + `animate`. UI-SPEC line 477 explicitly retires this pattern. Replace with vanilla React + CSS class toggle.

**Core pattern (vanilla React + CSS class flip)** — sourced from RESEARCH.md lines 699-739:
```typescript
export default function Counter({ target }: CounterProps) {
  const [displayed, setDisplayed] = useState(0);
  const prevCharsRef = useRef<string[]>(['0','0','0','0','0']);
  const timersRef = useRef<number[]>([]);

  useEffect(() => {
    setDisplayed(target);
    // schedule per-digit flips with stagger (0, 40, 80, 120, 160 ms)
    // CSS @keyframes digitOut/digitIn handle the visual; React just toggles .flip
    return () => { timersRef.current.forEach(window.clearTimeout); };
  }, [target]);

  const chars = String(displayed).padStart(5, '0').split('');

  return (
    <div className="counter">
      <div className="digit-row" aria-label="Sign ups so far">
        {chars.map((ch, i) => (
          <DigitCell key={i} char={ch} index={i} />
        ))}
      </div>
      <div className="counter-label">
        <span className="dot" aria-hidden="true" />
        <span>Sign ups so far</span>
      </div>
    </div>
  );
}
```

**DOM (per digit, 5x — Landing.html lines 1381-1385):**
```html
<div class="digit"><span class="d-cur">0</span><span class="d-next">0</span></div>
```

**Flip mechanics** (lift verbatim from Landing.html lines 1774-1801 + RESEARCH.md):
1. On `target` change, compute `chars = String(target).padStart(5, '0').split('')`
2. For each digit `i` where `chars[i] !== prevCharsRef.current[i]`:
   - Set `.d-next` text content to new char
   - Force reflow: `void el.offsetWidth`
   - Add `.flip` class
   - Schedule `setTimeout(() => { /* commit: .d-cur = new char, remove .flip */ }, 500)`
   - Stagger via `setTimeout(triggerFlip, 40 * i)` (per UI-SPEC `<specifics>` 4th bullet)
3. Cleanup: clear all timers on unmount + on next `target` change

**Initial mount behavior** (UI-SPEC line 461): render `00000` first, then animate to `target` on first paint. The `useState(0)` + `useEffect` that calls `setDisplayed(target)` does this naturally.

**Width logic** (UI-SPEC line 464): always render 5 cells. The `target >= 10000 ? 5 : ...` width logic from the current Counter is dropped — visual cell count is always 5.

**StrictMode landmine** (RESEARCH.md Risk #6): the `useEffect` MUST return a cleanup that clears pending `setTimeout`s — React 19 + StrictMode double-invokes effects in dev.
