# 01.5-05 — Counter rewrite (5-digit CSS flip-card)

## What was built

Full rewrite of `src/components/Counter.tsx` from a Motion-driven odometer (`useMotionValue` + `useTransform` + `animate`) into a vanilla React + CSS-keyframe-driven 5-digit flip-card counter. Mirrors the prototype's `Landing.html` `setCount` algorithm byte-for-byte while preserving the outward prop signature so the call site `<Counter target={waitlistCount ?? 115} />` in `App.tsx` (Wave 3) compiles unchanged.

## What changed

| Before (Motion odometer) | After (CSS flip counter) |
|--------------------------|--------------------------|
| `<motion.span>{display}</motion.span>` — single span with a transforming number | `<div class="counter">` containing `.digit-row` (5 `.digit` cells, each with `.d-cur` / `.d-next`) + sibling `.counter-label` (`.dot` + "Sign ups so far") |
| Dynamic width based on target tier (3/4/5 digits) | Always 5 cells, leading zeros padded |
| Motion's `easeOut` 1.2s tween | 500ms `digitOut`/`digitIn` keyframe pair (declared in `src/index.css` by 01.5-02), staggered 40ms × index across cells |
| `controls.stop()` cleanup | `clearTimeout` on all pending handles + snap-finalize d-cur/d-next/.flip to last target so StrictMode double-invocation never leaves the DOM mid-flip |

## Algorithm (mirrors prototype's `setCount`)

1. Compute `newChars = String(target).padStart(5, '0').split('')`.
2. For each digit `i` whose char changed from `prevCharsRef.current[i]`:
   - At `t1 = i * 40ms`: set `.d-next` textContent, remove `.flip`, force reflow (`void d.offsetWidth`), add `.flip` (kicks off `digitOut` on `.d-cur` and `digitIn` on `.d-next`).
   - At `t2 = t1 + 500ms`: commit by setting `.d-cur` textContent to the new char and removing `.flip`.
3. Update `prevCharsRef.current` to `newChars`.
4. Effect cleanup clears all timers AND snap-finalizes each digit so a half-flipped state cannot survive a StrictMode unmount/remount (RESEARCH Risk #6).
