<decisions>
## Implementation Decisions

### Animation Library Boundary

- **D-01:** FirstLetter step transitions (write → email → success and back) use **pure CSS classes** (`.fl-step-entering` / `.fl-step-leaving` + `stepIn` / `stepOut` keyframes declared in `src/index.css`). No `motion/react` `AnimatePresence` wrapper. Rationale: the prototype already tuned the timings (300ms out + 400ms in, `ease`); re-deriving them through the motion library risks subtle drift from byte-perfect parity, and CSS is the lighter-weight path.
- **D-01a:** This decision applies ONLY to FirstLetter step transitions. UI-SPEC's library split is otherwise authoritative: `motion/react` for scroll-reveals (hero, How cards, Research, FirstLetter head), raw CSS `@keyframes` for ambient effects (`wls-stamp`, `wls-bob`, `ping`, `countBump`, `blink`, `digitOut`, `digitIn`, `waxDrop`).

### Asset Sourcing

- **D-02:** `paper-light.jpg` is **self-hosted in this phase**. Download once from `https://i.postimg.cc/yWZ0XSgh/lightpaper.jpg`, commit to `public/assets/paper-light.jpg`, update the `.fl-pad-bg` CSS rule to reference `/assets/paper-light.jpg`. No `// TODO(CONTENT-03)` comment is needed because CONTENT-03 closes here. Rationale: ~5-minute task; eliminates third-party CDN risk immediately; closes a Phase 5 requirement early.
- **D-03:** All five required PNG assets (`separator-ink.png`, `step-write.png`, `step-seal.png`, `step-open.png`, `wax-seal.png`) are copied from `/tmp/sealed-design/sealed-prototype-landing-page-remix-remix/project/assets/` into `public/assets/` during the foundational task. All 5 are confirmed present (verified 2026-05-28; total ~1.4MB).
- **D-04:** `Landing.html` + the same 5 PNGs are **also** snapshotted into `.planning/reference/` at the start of Phase 1.5. `.planning/reference/Landing.html` becomes the verifier's source of truth for "side-by-side parity" so verification is reproducible in any future session even if `/tmp/` is wiped. Rationale: ~1.5MB one-time repo cost vs. losing the reference mid-phase if macOS cleans `/tmp/`.

- **D-05:** Delete `showSticky` `useState` + scroll-listener `useEffect` + `setShowSticky` call during the App.tsx rewrite. CLAUDE.md already flagged it as a dead-state anti-pattern; UI-SPEC Follow-Up #3 makes the deletion explicit (no "agent discretion" carry-forward). Note the deletion in the relevant plan's `<done>` block.

- **D-07:** Remove now-unused inline icon imports from `App.tsx` (`PenLine`, `Lock`, `Inbox`, `Users`, `ChevronRight`, `Twitter`, `Instagram`) once the new components own their own icons. Keep `lucide-react` as a project dependency — non-decorative icons in the new components may still use it.

## Specific Ideas

- **Side-by-side parity verification** — The verification plan must open `.planning/reference/Landing.html` in a browser alongside the dev server (`npm run dev`) and walk through every section in the UI-SPEC's "Section-by-section parity" checklist (Acceptance Gates). This is the canonical test for "pixel-faithful."
- **Animation timing precision** — D-01's CSS classes use the prototype's exact `stepOut` (300ms `ease`) and `stepIn` (400ms `ease`) timings. The implementer should lift the keyframe declarations verbatim from `Landing.html` rather than re-deriving them.
- **Asset workflow ordering** — All three asset moves (PNGs to `public/assets/`, `paper-light.jpg` download, `Landing.html` + PNGs to `.planning/reference/`) should land in the same foundational task or wave so subsequent component tasks have stable inputs.
- **Counter mount animation** — On initial mount the Counter renders `00000` and animates to the real `target` (e.g., `00115`). The width is always 5 cells regardless of the actual count, matching the prototype's fixed-width design. Implementation uses `setTimeout` to toggle a `.flip` class per digit with the stagger pattern (0ms, 40ms, 80ms, 120ms, 160ms) — no `useMotionValue` / `useTransform`.
- **Typewriter trim** — Update `typewriterPhrases` export in `Typewriter.tsx` to the 13-item list from UI-SPEC §"Typewriter phrases". Drop the existing 14th phrase entirely.

</specifics>
