# 01.5-07 — Typewriter trim + FirstLetter state machine rewrite

## What was built

Two-part change: a small surgical edit to `Typewriter.tsx` (drop one phrase, swap caret class) and a full rewrite of `FirstLetter.tsx` from an `AnimatePresence` + lucide-icons implementation to a pure-CSS-driven 3-step state machine matching `.planning/reference/Landing.html` lines 1532–1692 byte-faithfully. The outward contract is preserved verbatim so App.tsx's Wave-3 wiring compiles unchanged.

## Tasks completed

### Task 1 — `src/components/Typewriter.tsx`

Two minimal edits:

1. Trimmed `typewriterPhrases` export from 14 to 13 entries by dropping `"To realize one day you were exactly where you needed to be"` (was index 9 — confirmed identical to the prototype's curated 13-entry list).
2. Swapped the caret span from `<span className="animate-pulse ml-1">|</span>` (Tailwind animate-pulse) to `<span className="fl-caret" aria-hidden="true">|</span>`. The `.fl-caret` class is consumed by the global `@keyframes blink 1.1s steps(1) infinite` rule in `src/index.css` (Plan 01.5-02), giving the prototype's exact 1-second blink rhythm. Added `aria-hidden` because the caret is decorative.

### Task 2 — `src/components/FirstLetter.tsx` (484 lines, full rewrite)

Three-step state machine.

**Top-level structure:**
- `<section id="first-letter" className="first-letter">` → `.fl-inner`
- `.fl-eyebrow` ("Try it now")
- `motion.div.fl-head` with h2 "Your first letter *starts now.*" + sub copy "Send a letter to your future self, and we'll deliver it on **January 1, 2027.**"
- `motion.div.fl-stage` containing the three `.fl-step` siblings
- `motion.div.fl-promise` ("Secure · Delivered Jan 1, 2027 · Only you can read it")

**State:**
- `step: Step` — currently displayed step (`'write' | 'email' | 'success'`)
- `leavingStep: Step | null` — step currently animating out
- `enteringStep: Step | null` — step currently animating in
- `letter: string`, `email: string`, `daysToDelivery: number`
- `transitioningRef: useRef<boolean>` — debounce double-clicks during transition
- `timersRef: useRef<number[]>` — StrictMode-safe cleanup

**Transition algorithm (`transitionTo`):**
1. If already transitioning or step unchanged, no-op.
2. Set `leavingStep = step` → React rerenders with `.fl-step .fl-step-leaving` on the current container → CSS `stepOut` keyframe runs for 300ms.
3. After 300ms: set `step = next`, clear `leavingStep`, set `enteringStep = next` → React rerenders with `.fl-step .fl-step-entering` on the new container → CSS `stepIn` keyframe runs for 400ms.
4. After 400ms: clear `enteringStep` → container drops back to plain `.fl-step`.
5. All other steps render with `.fl-step .fl-step-hidden` (display: none).

**Step 1 — Write:**
- `.fl-pad` with `.fl-pad-bg` (paper-light texture) and `.fl-pad-content`
- `.fl-pad-body` (inline `paddingTop: 8, fontSize: 22, fontWeight: 600`) containing:
  - `.fl-typewriter` rendering `<Typewriter phrases={typewriterPhrases} />` while `letter` is empty (vanishes once the user starts writing — matches prototype)
  - `<textarea className="fl-textarea">` with `spellCheck={false}`, controlled by `letter`, auto-growing via `style.height = scrollHeight` on input
- `.fl-pad-foot` (inline `justifyContent: 'flex-start'`) with live `{wordCount} words`
- `<button className="fl-cta">Seal & send</button>` disabled while letter is empty

**Step 2 — Email (envelope):**
- `.fl-pad.fl-pad-email`
- `.fl-stamps` (left): Stamp 1 — wavy cancellation lines + "FIRST CLASS · SEALED"
- `.fl-stamps-right`: Stamp 2 — circular `SEALED · FIRST CLASS · / MMXXVI / SEALED / ★ / YOUR FUTURE SELF`; Stamp 3 — hexagonal `YOUR FIRST LETTER / ✦ / → 14 MAY 2026 ← / SEALED / TO YOUR FUTURE SELF`
- `.fl-pad-content` (inline `padding: '106px 0 0', justifyContent: 'center'`)
- `.fl-address-block` → `.fl-address-label` "Where should we send this?" (inline Space-Mono + width 444)
- `<form onSubmit={handleEmailSubmit}>` containing:
  - `.fl-address-to-row`: `.fl-address-to-label` "To" + `.fl-email-field` `type="email"` `required` placeholder `your@email.com` + `.fl-arrow-btn` "→"
  - `.fl-env-actions`: `.fl-back` "← Back" (transitions back to write)

**Step 3 — Success (envelope back):**
- `.fl-pad.fl-pad-success` → `.fl-env-back`
- `.fl-env-flap` SVG (preserveAspectRatio="none" 800×440 triangle fill)
- `.fl-wax-seal` containing `<img src="/assets/wax-seal.png" width={140} height={143}>` (the wax-drop keyframe targets this class in 01.5-02)
- `.fl-env-caption`: "We'll deliver it on **January 1, 2027** · in **{daysToDelivery} days**"

**daysToDelivery computation:**
```ts
Math.max(0, Math.ceil((new Date(2027, 0, 1).getTime() - Date.now()) / 86_400_000))
```
Initialized via `useState` with a lazy initializer. Refreshed every 60 s via a setInterval that is set up only while `step === 'success'`, cleared on unmount and on step change.

**initialEmail handling:** `email` state initializes to `initialEmail ?? ''`. A `useEffect([initialEmail])` re-syncs the email if `initialEmail` flips from undefined to a value mid-flow (App.tsx may pass it after the waitlist signup), but only when `email` is still empty to avoid clobbering user edits.
