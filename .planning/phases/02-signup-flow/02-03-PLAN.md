State-step ordering (locked by D-06 + RESEARCH §"Edge Function Pipeline" lines 200-234):
1. CORS preflight (OPTIONS short-circuit).
2. Method check (POST or 405).
3. Extract IP from `x-forwarded-for` first entry / `x-real-ip` / `'unknown'`.
4. Parse JSON body; validate `email` and `turnstileToken` are non-empty strings.
5. Turnstile siteverify; on failure return `{ state: 'turnstile_failed' }` 200 (NOT 4xx — the client treats this as a known state).
6. (Per D-06 fine-print) 4-state lookup BEFORE rate-limit check. If state is `unverified` / `verified_no_letter` / `verified_with_letter`, log `duplicate_*` outcome and return the matching state code. This is how same-email repeats don't trip the rate limit.
7. (State is `new`) Rate-limit check: count attempts from this IP in the last 24h. If count >= 3, return `{ state: 'rate_limited', retry_after: 86400 }` 429.
8. (State is `new`, under limit) admin.createUser → waitlist_signups insert → signup_attempts insert (outcome 'success') → `// TODO(Phase 3)` comment → return `{ state: 'success' }` 200.
