# Quick Task 260604-o2f: Improve email deliverability

## Problem
The first real send from the new `sealedapp.io` domain landed in Gmail's **junk
folder**, even though mail-tester scores 10/10. Authentication (SPF/DKIM/DMARC) is
correct — this is **inbox placement / reputation**, which a brand-new sending
domain has to earn. We can push the controllable signals in our favor.

## Fix (the controllable levers, highest-impact first)
1. **`List-Unsubscribe` header** on every send — Gmail weighs this heavily and
   expects it of list mail. mailto-based (no HTTPS one-click endpoint yet).
2. **Plain-text alternative** (`text/plain` part) alongside the HTML — a standard
   "real mail, not spam" signal. Best-effort: never blocks the HTML send.
3. **On-brand footers** — "why you're receiving this" (trust) + an Unsubscribe
   link on 1A (waitlist). 1B (transactional verify) gets why-received only; the
   header still ships.

## Tasks
### Task 1 — Resend wrapper (`_shared/resend.ts`)
- Add optional `text` + `headers` to `ResendSendArgs`; include in the API body
  only when present. **verify:** `deno check` passes.

### Task 2 — Wire sends (`join-waitlist/index.ts`)
- `renderEmail()` helper → `{ html, text? }` (plain-text best-effort, try/catch).
- `LIST_HEADERS` const from `SEALED_UNSUBSCRIBE_MAILTO` (default info@sealedapp.io).
- All three send sites (1A new, 1A resend, 1B test) pass `text` + `headers`.

### Task 3 — Template footers (`WaitlistConfirmationEmail.tsx`, `SealLetterEmail.tsx`)
- 1A: why-received + Unsubscribe mailto (matches header default).
- 1B: why-received only (transactional).

## must_haves
- **truths:** every send includes a `List-Unsubscribe` header and (when render
  succeeds) a plain-text part; plain-text failure never blocks the HTML send.
- **artifacts:** 4 files in SEALED-org (resend.ts, index.ts, 2 templates).
- **key_links:** Resend `/emails` API `text`/`headers` fields; Gmail bulk-sender
  guidance (List-Unsubscribe).

## Out of scope (deferred / needs input)
- HTTPS one-click unsubscribe endpoint + `List-Unsubscribe-Post` + auto-unsubscribe
  webhook (STATE.md already defers the webhook to v2).
- **Physical mailing address** footer line (CAN-SPAM) — needs the real address
  from Nour; omitted rather than fabricated.

## Deploy / verify
- Requires `supabase functions deploy join-waitlist` to take effect.
- Confirm on the next real send: email lands in inbox (not junk); "Show original"
  has a `List-Unsubscribe` header and a `text/plain` part.
